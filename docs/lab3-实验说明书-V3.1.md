必须掌握的体系结构规范

以下为 RISC-V SV39 体系结构硬件规范定义，需严格对照 RISC-V 特权级架构规范实现：

• 39 位虚拟地址（Virtual Address, VA）划分为：VPN[2] (9位) | VPN[1] (9位) | VPN[0] (9位) | 页内偏移 (12位)；根页表物理基地址存放在控制与状态寄存器（CSR）satp 中，其 MODE 字段设为 8 表示启用 SV39 分页模式。

• 每个页表占用一个物理页（4KB），每个页表项（Page Table Entry, PTE）占用 8 字节，每页包含 512 个页表项；硬件通过三级页表逐级寻址，第三级（叶子节点）得到物理页号（PPN），拼接 12 位页内偏移形成物理地址（Physical Address, PA）。

• 页表项低位标志位：V（有效位）、R/W/X（读/写/执行权限位）、U（用户态访问权限位）。当一条 PTE 的 R/W/X 权限位全为 0 时，表示该项为指向下一级页表的非叶子节点（中间节点）。

• 修改页表结构或切换 satp 寄存器后，快表（TLB，Translation Lookaside Buffer）中可能残留陈旧的地址映射缓存，必须通过执行 sfence.vma 指令刷新 TLB（预置 riscv.h 已提供封装）。在设计笔记中需明确说明刷新时机以及未刷新的后果（在多核环境下 sfence.vma 仅刷新当前核心的 TLB，本实验为单核环境，相关原理作为思考题留档即可）。

1. 分阶段任务指引

阶段一：物理页分配器

目标：完成 kinit、kalloc、kfree 核心内存管理例程的实现，系统能够精确统计并维护空闲物理页总量。

设计决策点：

• 如何利用空闲物理页自身存储链表节点（隐式空闲链表结构），避免引入额外的元数据内存开销？

• 数据结构在内存回收路径上的时间复杂度分析：若基于单向有序链表实现 LAB3_ALLOC_ORDER=0（升序分配），分配操作的时间复杂度为 $O(1)$，但单页释放时需按地址顺序插入链表，导致单次插入复杂度为 $O(n)$。在 memcap 压力测试批量释放数万物理页的场景下，总体时间复杂度将达到 $O(n^2)$，在 QEMU 模拟器环境下耗时可达数分钟，极易与系统死锁现象混淆。若采用位图管理（每个物理页对应 1 个比特位，128MB 物理内存对应的元数据开销仅约 4KB），页释放操作的时间复杂度为 $O(1)$，分配时通过检索最低空闲位即可满足升序语义。设计笔记中需对两种数据结构的时间与空间开销进行对比分析，并说明最终选型依据。

• kinit 托管物理内存的起始地址与结束地址如何界定？（链接脚本导出的 kernel_end 符号指示了内核镜像末尾——注意本课程链接脚本中的符号名称为 kernel_end，而非传统 xv6 教程中的 end；需同时结合 LAB3_MEMCAP_DELTA 配额宏计算可用上限。）

• kfree 释放物理页前填充特定垃圾数据（Junk Data）的目的是什么？kalloc 分配物理页前为何必须清零？请分别从释放后悬挂指针排查与数据安全隔离两个角度进行分析。

验证方法：在 main() 中编写临时验证逻辑：循环分配与释放若干物理页，检查页指针是否满足 4KB 对齐、空闲页计数是否满足守恒、新分配页的数据是否已完全清零；随后持续分配直至触碰配额上限，确认 kalloc 正确返回空指针。功能验证通过后移除测试代码（或使用条件编译宏 #ifdef 进行隔离，正式构建时不开启该宏即可）。

目标：完成 walk（页表遍历）与 mappages（建立映射）的实现，构建虚拟存储管理的核心基础设施。

设计决策点：

• 中间级页表项与叶子节点页表项在标志位上有何本质区别？walk 遍历至第三级（叶子节点）时，返回的是物理地址还是对应页表项（PTE）的指针？为何必须返回 PTE 指针？

• 当为已存在有效映射的虚拟地址重复调用 mappages 时，系统应当覆盖、返回错误码还是触发内核停机？说明设计理由。

• 当 kalloc 在分配中间级页表时失败，回滚操作从哪一页开始拆除？拆除过程中各级页表与物理页的释放边界如何划分？

验证方法：构造测试页表建立多段虚拟地址映射，使用 walk 反查并校验各项权限标志位；通过临时缩减可用页配额人为触发分配失败，发起需要分配大量中间级页表的大区间映射测试，验证映射建立失败时能否完整回滚中间资源，且空闲页统计值恢复原状。（配额受限验证方法：配额宏为只读配置不可直接修改，可通过循环调用 kalloc 分配物理页，将空闲页数量临时消耗至个位数——物理页指针暂存于数组中备用，测试结束后按序释放——随后发起需要大量中间级页表的大区间映射，触发分配中途失败以检验回滚逻辑。）

阶段三：内核页表构建与分页机制使能

目标：内核自身启用 SV39 分页机制，执行 make qemu 后系统能够平稳引导至控制台，确保内核关键内存区域无遗漏映射。

设计决策点：

• 内核页表必须包含哪些内存区域的映射？逐项明确映射清单：通用异步收发器（UART）与平台级中断控制器（PLIC）为必需映射项（内核驱动直接访存项；核心本地中断控制器 CLINT 为可选映射项，需说明时钟访问采用 CSR 还是外设寄存器的理由）；内核镜像与全部可用物理内存必须恒等映射至 PHYSTOP（注意不可仅映射至内核镜像末尾：启用分页后，内核直接读写的空闲物理页、页表页及进程数据页均分布在镜像之外的物理内存中）；跳板页（trampoline）保持同址映射。

• 控制与状态寄存器 satp 的数值构成（MODE 模式字段 + 根页表物理页号 PPN）如何计算？

• 写入 satp 寄存器前后是否需要执行 sfence.vma 指令？多核并发场景下的处理原则是什么？

阶段四：用户页表构建、受控拷贝、地址空间动态扩展与结构观测

目标：为用户进程建立独立的虚拟地址空间；以 copyin / copyout 全面替换内核对用户指针的直接解引用；完成 fork/exec 的页表化改造；支持通过 sbrk 动态调整用户地址空间大小；dump_pagetable 格式符合规范。

从 lab2 迁移至增量包预置跳板（trampoline.S）时，需明确以下两项关键机制变更：

• stvec 陷入向量的切换位置发生迁移：预置的 uservec 在完成现场保存后仅执行“切换至内核页表并调用陷入分发函数”，并不负责重置 `stvec`；将 stvec 切换为内核态中断向量的逻辑，必须显式放置在陷入分发函数（如 usertrap）的第一行；在返回用户态前再重新将 stvec 指向 uservec。lab2 自行实现的陷入入口通常在汇编中完成该切换，迁移时需防止遗漏。

• 移除 lab2 采用的固定物理基地址方案：若在 lab2 中为规避小地址绝对寻址缺陷采用了固定基地址重链接规则，在本实验中必须恢复用户程序按基地址 0 链接并装载至虚拟地址 0。在独立的用户页表映射下，绝对寻址在虚拟地址空间中天然合法；若未移除旧的固定物理基地址重链接规则，用户程序加载执行将发生异常崩溃。

设计决策点：

• 用户页表需要映射哪些区域？各自的访问权限与内核页表有何区别？（严格对照 lab0 绘制的地址空间快照图；注意本课程的用户空间内存布局与原版 xv6 存在差异，低地址依次为代码段/数据段、保护页、用户栈，堆空间位于更高地址。在遍历或 fork 复制地址空间遇到未映射的保护页（guard page）空洞时，应直接跳过而非判定为错误。）

• 用户代码段为何严禁配置写权限（W 位）？课程标准测试用例 badaccess 的 TEST-3a 专门校验写代码段是否会被内核强制终止。由于平铺二进制镜像（flat binary）不包含 ELF 格式的段属性信息，如何将代码段与只读数据段的边界信息传递至内核装载模块？需理清三步链路：① 构建期提取边界：编译镜像时可通过 readelf 提取程序 ELF 文件的各段大小与位置；② 传递至内核：通过扩展内嵌程序表表项字段，将边界信息载入内核；③ 内核装载时判定：按页判断虚拟地址区间并赋予不同权限位。此外需注意：当整个程序尺寸小于 4KB 时，只读代码段与可读写数据段若落在同一物理页内，页粒度的权限控制将无法隔离；预置的 user.ld 不可直接修改，但可通过构建脚本生成派生链接脚本（例如在数据段起始位置插入一页对齐声明），确保数据区从全新的页边界起始对齐。

• 返回用户态时能否在 C 函数内直接写入 satp 并继续顺序执行？需分析页表切换瞬间指令计数器 PC 取指的连续性：由于切换至用户页表后当前内核 C 代码的虚拟映射立即失效，返回路径必须经由在用户与内核页表均建立同址映射的跳板页（trampoline）完成，C 语言侧需通过高地址间接函数调用将执行流转移至跳板汇编入口。

• 当 copyin 遇到跨越物理页边界的缓冲区、页尾仅剩余部分字节未拷完、或遇到缺失 PTE_U 权限的非法物理页时，分别应如何处理？

• sbrk 扩展地址空间时若物理内存配额耗尽应如何处理？（必须返回 -1，已建立的中间映射与物理页全部安全回滚，内核保持正常运行；课程标准测试 memcap 即针对该异常路径进行边界考核。）

3. 排查思路

故障现象

优先排查方向

写入 satp 激活分页后系统停机或复位重启

检查内核页表映射清单是否存在地址缺失：内核代码段是否具备执行权限（X）？外设物理地址（如 UART、PLIC）是否已建立恒等映射？

启用分页后串口输出乱码

确认 UART 访问是否使用正确的映射地址；确认写入 satp 变更根页表基址前后是否已执行 sfence.vma 指令刷新 TLB。

启用分页后首次调用 kalloc（例如建立首个页表页或内核栈映射）即触发缺页异常

检查内核页表是否仅恒等映射到内核镜像末尾；内核镜像结束地址至 PHYSTOP 之间的可用物理内存空间同样必须建立恒等映射（参见阶段三说明）。

切换至用户态时触发缺页异常（scause = 12/13/15）

检查用户虚拟空间各页表项是否包含 PTE_U（用户态访问权限）；检查 sepc 指向的用户代码段页表项是否已配置执行权限（X）。

系统运行数秒后发生未响应停机，-d int 诊断日志中高频出现 store fault 异常且 sepc 落在 TRAMPOLINE 虚拟页面内

内核态时钟中断触发时 stvec 仍指向用户态向量：检查陷入处理函数入口是否已将 stvec 切换为内核态中断向量（预置 uservec 不负责该切换操作）。

物理内存耗尽时触发内核崩溃（Panic）

检查 kalloc 返回空指针（NULL）时，调用链各级函数是否均实现错误传递与资源回滚，排查是否存在未校验返回值直接解引用的缺陷。

memcap 测试长时间无输出反馈

排查物理页分配器在批量回收路径上的算法复杂度：若采用顺序链表插入导致 $O(n^2)$ 复杂度，耗时显著增加；建议改用位图管理机制。
