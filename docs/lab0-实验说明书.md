## 0. 开始之前：怎么读、读多久

**预计耗时**：绘制控制流图及梳理阅读路线约 6–8 小时；整理三份核心结构快照约 4 小时，合计约 **10–12 小时**（第 1 周内完成，快照部分可与 lab1 并行推进）。

> 如果超过 10 小时还没理清控制流图，请带着草稿去求助——遇到疑难是正常的，及时交流才能提升效率。

**阅读对象**：MIT 公开 xv6-riscv 源码仓库（课程平台提供链接或参考目录）。

> ⚠️ **两点注意**
>
> 1. 课程后续实验的接口约定与公开版存在多处差异（专属系统调用号分配、用户程序内嵌加载机制、诊断输出规范、每人不同的个性化参数），**不影响对核心机理的阅读理解**。
> 2. 参考树是**新版上游**：`usertrapret` 已更名 **`prepare_return`**、`sleep` 已拆两段式（**`sleep_prepare`**）。阅读时**以树内实际命名为准**，与旧版 book 或网上旧资料撞名属正常现象。

### 推荐阅读路线

按此顺序读，避免直接按文件字母顺序孤立阅读：

1. `user/sh.c` 的 `main` 循环 —— 先从"用户视角看发生了什么"
2. `user/usys.pl` ＋ `kernel/syscall.c` —— 一个系统调用如何跨越特权级边界
3. `kernel/trampoline.S` ＋ `kernel/trap.c` —— 特权边界上到底发生了什么（**先读 C 语言分发逻辑，汇编只看注释与跳转**）
4. `kernel/exec.c` ＋ `kernel/vm.c` 中的 `uvmcopy` —— echo 进程从何而来
5. `kernel/file.c` ＋ `kernel/console.c` —— 字符串 `"hi"` 如何输出到外设
6. 对照 xv6 book《Operating system interfaces》与《Traps and system calls》两章精读，书上的架构图与你的草图互相校对

### 阅读函数的方法

每读一个核心函数，思考三个问题：

- 它被**谁调用**？
- 它是否可能**阻塞睡眠**？若阻塞，**谁负责唤醒**它？
- 遇到错误分支时**如何回滚并返回**？

## 1. 实验任务

针对完整可运行的参考内核，全链条追踪 Shell 执行 `echo hi` 命令的全生命周期，交付**三份核心图纸**。

### 材料一：全系统控制流图（模块级）

从用户敲下回车键开始，到屏幕显示 `hi` 为止，按时序完整画出函数调用、系统调用、上下文切换与中断响应链路，**至少覆盖以下骨干节点**：

```
Shell: read → 阻塞等待 → (键盘/UART 中断触发) → fork → exec(echo) → wait
内核:  usertrap → syscall 分发 → ... → scheduler → ... → uart 驱动输出
echo:  main → write(1, "hi") → exit
```

**标注要求**：每个阶段必须明确标注

- 当前运行在**哪个栈**（用户栈 / 该进程内核栈 / 调度器专门栈）
- CPU 处于**何种特权级**（U 态 / S 态 / M 态）
- 是否**持有自旋锁**

📄 交付到 → [`notes/lab0/control-flow.md`](../notes/lab0/control-flow.md)

### 材料二：核心数据结构全景快照

选定一个关键截面时刻（**exec 刚刚执行完毕、echo 的首条用户指令尚未运行**），画出：

1. **进程表快照**：shell、echo、init 等进程的 `state`、`parent`、`pagetable`、`sz` 以及打开的文件描述符数组
2. **页表快照**：echo 进程虚拟地址空间的完整映射树（trampoline、trapframe、代码段、用户栈、guard page、堆区，分别标明**虚拟地址区间与 PTE 权限位**）
3. **文件表快照**：进程 `ofile` 数组、系统 `file` 结构、`inode` 节点对标准输出设备（stdout）的引用链路

📄 交付到 → [`notes/lab0/data-structures.md`](../notes/lab0/data-structures.md)

### 材料三：一次时钟中断的微观旅程

任选一个正在运行的用户进程，详细描述从时钟中断到来（`scause = 0x8000000000000005`）进入 `usertrap`，到最终执行 `sret` 返回用户态之间发生的**全部动作**，以及引发的进程让步（`yield`）与调度决策过程。

📄 交付到 → [`notes/lab0/timer-interrupt.md`](../notes/lab0/timer-interrupt.md)

## 2. 启发性自查问题（思考题，不上交）

> 不判分、不收缴，但 **lab1 验收问答直接从中抽选**。

**第一层（描述性）**
- `fork` 返回后，父进程与子进程分别从哪一行继续执行？为什么两者的返回值不同？
- `exec` 加载新镜像时，原进程的虚拟地址空间发生了什么变化？

**第二层（机制性）**
- `fork` 复制页表时，为什么最高处的 trampoline 页必须映射为只读，而不需要重新分配物理页？
- Shell 的 `read` 系统调用返回之前，Shell 进程处于什么状态？最终是由谁将其唤醒的？
- echo 发起的第一次 `write` 系统调用，底层是如何一步步转化为 UART 硬件寄存器写入的？

**第三层（预测性）**
- 如果内核启动代码中创建第一个用户进程的调用被注释掉，系统会停在何处？现象是什么？
- 如果子进程 `exec` 完成且已退出，而父进程尚未调用 `wait`，此时进程表中子进程处于什么状态？
- echo 执行完毕调用 `exit`，它打开的标准输出文件结构是如何保证不发生资源泄漏的？

📄 作答记录 → [`notes/lab0/thinking-questions.md`](../notes/lab0/thinking-questions.md)
